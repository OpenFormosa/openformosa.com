# Contributing to OpenFormosa / 參與貢獻

Thank you for helping build open AI for Taiwan's languages. Everyone who contributes is OpenFormosa.

感謝你參與。每一位貢獻者，都是 OpenFormosa。

## Start here / 從這裡開始

1. Join [Discord](https://discord.gg/N4YnrjjcW7) and say hello in the welcome channel.
2. Pick a [good first issue](https://github.com/issues?q=is%3Aopen+is%3Aissue+org%3AOpenFormosa+label%3A%22good+first+issue%22), or report one model error in text.
3. Open a pull request. A reviewer will help you finish it.

See [GOVERNANCE.md](GOVERNANCE.md) for roles, decisions, and credit.

## Project scope

OpenFormosa is focused on model training, evaluation, release documentation, and reproducibility. It does not collect community datasets through GitHub, Discord, the website, or public issue templates.

## Do not upload raw data / 不要上傳原始資料

Do not attach audio, transcripts, images, PDFs, identity documents, private messages, enterprise data, student records, medical data, financial data, or any non-consented speech to GitHub issues, pull requests, or Discord. Describe errors in text instead.

## Useful contributions

All of these count, and all of them are credited:

- Benchmark definitions, scoring scripts, and documented error cases.
- Training recipe notes, reproducibility fixes, and tooling.
- Taigi, Hakka, and Indigenous language review (no programming needed).
- Model-card improvements, documentation, and Chinese–English translation.
- Safety reviews, design, website work, and community support.

## Sign your commits (DCO)

We use the [Developer Certificate of Origin](https://developercertificate.org/). Add a sign-off line to every commit:

```bash
git commit -s -m "Describe your change"
```

This adds `Signed-off-by: Your Name <you@example.com>`. You keep the copyright of your contribution and release it under the repository's license. You may use a handle instead of your legal name.

## Credit

Accepted contributions are listed in the contributor list, in release notes, and in technical reports authored as "OpenFormosa Contributors". Tell us in your pull request if you prefer a handle.

## Required review

Maintainers may reject issues or pull requests that include raw private data, unclear rights, privacy risks, unsafe model behavior, or claims without reproducible evidence.
